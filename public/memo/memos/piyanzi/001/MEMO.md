### 作战阶段（每一步开干前确认）

| 阶段 | 做什么 | 边界 |
| --- | --- | --- |
| **预检** | 检索、比对、拟稿、预览命名与归档结构、出预检报告 | 不覆盖正式检查单；不往正式输出目录落最终件 |

## 分阶段对齐清单（问清再干；可一步一问）

### 1 定范围

1. 检查单路径？哪张表？符合性声明在哪一列？  
2. 写哪些行？全部 / 按分工 / 按审计点编号 / 点名序号？  
3. 只要「符合」，还是也可能「不适用」？  

未指定行 → 先问清，再开写或预检。

### 2 定手册

1. 手册目录与文件形态（PDF / Word / Markdown）？  
2. 正式书名与文件名对照？  
3. 查找优先顺序？  
4. 不可检索材料是否已转文本？未转 → 先转或跳过该本。  

### 3 填符合性声明 / 4 抽 PDF

填声明：按后文铁律与第一步～第四步执行；本步先确认是预检还是实写入。  
抽 PDF：确认输出根目录、行范围、整理标准（文件夹层级与命名**以主人当次要求为准**；未指定前先问清。抽页默认：文件名 `{手册名}{条款号}.pdf`，命中页±1，条款号高亮，排除目录/附录页）。本步同样先确认是预检还是实写入。

## 铁律

按作业顺序执行，不可颠倒；**唤醒后的阶段问答，插在一切写入之前**：

0. **阶段门禁。** 每一步都先确认是预检还是实写入；未确认前不改正式文件。实写入必须先备份。  
1. **开干前确认。** 未问清并得到用户答复前不写入。必问：检查单是哪一份（路径）、哪张表、填哪一列；参考手册有哪些（路径或目录）、优先顺序；若有二进制/不可检索材料，是否已转成 `.docx` / Markdown / 纯文本，或是否允许代抽文本。  
2. **完全基于手册原文。** 检索、摘录、符合性声明正文，全部来自手册已写明的文字。不得臆造条款号，不得改写、概括、补全、润色。填入的条款正文与手册对应段落逐字一致；绝对禁止擅自增删任何字词、标点、编号、子项。同一手册同一条款，正文只能有一种写法。全文 = 从该条款号起写到下一条同级编号之前（含子项）。  
3. **必须做语义比对与语义复合。** 程序查找、关键词命中、条款号回搜、脚本比对，都只是过程。最终采用前，必须把检查单该条要求与候选手册原文做语义比对：是否同一对象、同一动作、同一条件。可多手册、多条款做语义复合，但每一段写入正文仍须是各自手册的原文。关键词对上、语义对不上 → 不用。语义对不上 → 不填或留空，不硬凑。  
4. **按原文写入符合性声明列。** 只改符合性声明列。语义比对通过的相关条款全部写入，不漏、不编。先按手册优先顺序，同一本里再按条款号排。不同条款、不同手册一律换行，不用分号或逗号把多条粘在同一行。每一行写「《手册名》条款号：〔该条全文〕」；同一本手册的下一条也换行，手册名仍写全。第一行以「符合性声明：符合，见」起头。句式：

```
符合性声明：符合，见《手册1》条款号A：〔全文A〕
《手册1》条款号B：〔全文B〕
《手册2》条款号C：〔全文C〕
```

不适用则：`符合性声明：不适用。〔可核对原因〕`  
5. **填完必核。** 每条写入后，单元格内条款全文与手册该条款并排核对；不一致则以手册原文覆盖后再核。只有原文一致且语义比对通过，这一条才算填完。  
6. **找不到就留空。** 不写「无相关内容」「无手册」等套话。不编造不适用原因；不适用须前提可核对。

## 第一步：语义拆解

从该条的检查项名称、要素、提示中抽出：对象、动作、条件。得到检索用词，并留下语义比对用的要求要点（第三步还要用）。

## 第二步：查找原文

目的：交叉定位候选原文。机械查找（Grep、脚本、条款号回搜）只负责找到位置；能不能用，留给第三步按铁律第 3 条做语义比对。

只在用户确认的手册里查。不猜条款号。优先手册先查，没有再查下一本。用户指定填哪几行就只填那几行。

同一本手册若拆成多个文件，检索时当作一本；写入时手册名用用户确认的正式名称，不把分册文件名写进符合性声明。判断「下一条同级编号」以条款编号为准，不以标题标记层级为准。

检查单若是表格（如 `.xlsx`），用读表方式定位行与列，不要把检查单文件本身当手册去关键词检索。

条款边界（对应铁律第 2 条）：从本条编号起，到下一条同级编号之前；其下子项全部算入本条。写入正文必须来自把该条连续读完的结果。

默认走法：先粗读、再精读、再读周边。这是一条可用路径，不是唯一路径。

### 材料形态：先可读，再检索

手册不一定是 Markdown。常见还有 Word（`.docx`）、纯文本、已导出的 `.md` / `.txt` 等。Grep / Read 只对「可读文本」高效；二进制先变成文本再查。


| 形态                    | 先做什么                                | 再怎么查                                    |
| --------------------- | ----------------------------------- | --------------------------------------- |
| `.md` / `.txt` 等纯文本   | 直接用                                 | Glob → Grep → Read                      |
| `.docx`               | Python 抽正文成临时文本，或先转成 `.md` / `.txt` | 对文本 Grep / Read；不对 `.docx` 二进制做关键词 Grep |
| `.doc`、扫描 PDF、加密包等二进制 | 建议用户先转成 `.docx` 或 Markdown / 纯文本    | 转完前不硬解、不猜条款；可先填其他已可读手册的条目               |


- 不能稳定抽出正文：停，请用户转换，不用乱码或半截 XML 填单。
- Agent 可代转的，落盘为 `{手册名}.md` 或 `.txt`；后续只搜转换结果；原件不动。
- 转换结果只作检索载体；写入时手册名用用户确认的正式名称。

Word（`.docx`）抽文本（Shell + Python）：

```python
from docx import Document
doc = Document(r"{docx路径}")
lines = [p.text.strip() for p in doc.paragraphs if p.text.strip()]
for table in doc.tables:
    for row in table.rows:
        for cell in row.cells:
            t = cell.text.strip()
            if t:
                lines.append(t)
open(r"{输出txt或md路径}", "w", encoding="utf-8").write("\n".join(lines))
```

无 `python-docx` 时，可用 zip 解析 `word/document.xml` 抽 `<w:t>`，写出 UTF-8 文本后再 Grep / Read。

### 粗读

只回答：哪几份手册、哪一章大概有关。不抄条款。

- Grep：`path` 为手册目录或已抽文本，`pattern` 用 1～2 个核心词（多词 `|`），`glob` 为 `*.md` / `*.txt`，`output_mode` 为 `content` 或 `files_with_matches`，`head_limit` 约 40。不加 `-A` `-B` `-C`。不对 `.docx` 二进制 Grep。
- 先 Glob 按后缀分流；`.docx` 先 Shell 抽文本再 Grep。
- Read 文本手册目录/章节标题，判断该进哪一章。

命中太多：收窄词或改单一文件。命中为零：换同义说法再粗读，不直接认定没有。

### 精读

确认是不是该要的那一款，不是邻近另一款。

- Grep：`path` 为粗读命中的那一个文件，`pattern` 更窄或已见条款号片段，`-C` 2，`head_limit` 约 20。
- 或从标题行号 Read 一小段（`limit` 约 40）看小标题。
- 用第二个关键词再 Grep；两次落在同一条款，再读周边。

`-C` 与短 Read 只确认位置，不截句当全文。

### 读周边

- Read：`offset` 在本条标题前约 15～30 行，`limit` 从 80 起；不够则加大或续读，直到下一条同级编号。
- 必要时上下再读一节，核对章节归属。
- 折行表格以连续 Read 原文为准。

### 交叉达不到一致时

换路径再查：目录反查、换词、条款号回搜、下一本优先手册再走一遍。仍定位不到 → 该格按铁律第 6 条留空（还须经第三步确认语义后才最终留空或写入）。

### 工具调用样例（通用参考）

占位符换成用户确认的路径与拆出的词。顺序可改；本步只做交叉定位，采用与否在第三步。

假设：`{手册目录}`，`{优先手册}`（`.md` / `.txt` / `.docx`），抽完后 `{文本手册}`，`{宽词}`，`{窄词}`。

0. Glob：并行 `*.md`、`*.txt`、`*.docx` → 形态分流。文本 → 步骤 2；`.docx` → 步骤 1；其他二进制 → 请用户转换并跳过本手册。
1. Shell（仅 `.docx`）：抽成 `{文本手册}`；Read 抽查开头非乱码。之后 Grep/Read 只对 `{文本手册}`。
2. Grep 粗读：`path` 目录或文本，`pattern` `{宽词}`，`glob` `*.{md,txt}`，`head_limit` 40，无上下文。
3. Grep 精读：`path` `{文本手册}`，`pattern` `{窄词}`，`-C` 2，`head_limit` 20。
4. Read 短读（可选）：`limit` 40，核对章节。
5. Read 周边：取本条至下一条同级编号前的全文（候选原文）。
6. Grep 交叉（推荐）：另一关键词或条款号回搜；命中别处则回到粗读。

并行：步骤 0 可先跑；已是文本时 0 与 2 可同轮；3 与 4 可同轮。步骤 1 必须在对 Word 做 Grep 之前。步骤 5 依赖步骤 3 的行号。Shell 只做转换抽文本。

## 第三步：语义比对与复合

对第二步得到的每段候选原文，按铁律第 3 条与检查单该条要求比对（对象、动作、条件）。通过的留下，按手册优先顺序与条款号排好，供写入。不通过的丢掉。全部不通过 → 铁律第 6 条留空，或确认不适用后按铁律第 4 条写不适用。

## 第四步：写入与核对

**若为实写入：本步开始前必须已完成备份（见迎宾「实写入备份」）。**  
预检：只展示拟写入文本，或写入用户指定的草稿位置，不覆盖正式列。

按铁律第 4 条写入符合性声明列（全文须满足铁律第 2 条）。

写入后立刻按铁律第 5 条：原文逐字核对 + 再确认语义仍盖住检查项。通过后才下一条。

## 第五步：按条款抽取手册 PDF（迎审佐证）

符合性声明填完后，若用户要求做迎审佐证材料：从手册 PDF 中按条款抽出对应页面，按检查项归档。未问清范围与输出目录前不抽取。  
进入本步前再确认一次：是 **演习输出** 还是 **实产出**；实产出覆盖目录前要备份。

### 范围与确认

开干前确认：

1. 检查单路径、符合性声明所在列。  
2. 只抽谁的行（通常按「分工」列过滤，如仅本人；不默认全表）。  
3. 手册 PDF 目录（哪几本、正式书名与文件名对应关系）。  
4. 输出根目录。  
5. **归档怎么排**（文件夹层级、命名规则）——以主人当次要求为准；未说清前先问，不套某一类审计的固定目录。  

先做预检：解析声明中的全部「《手册》+条款号」，在 PDF 中定位正文页；预检通过或用户接受缺口后再批量抽取。

### 抽取规则

1. **整页抽取 + 条款号高亮。** 命中条款所在页整页取出；默认再各加前后一页（命中页 ±1）；首尾页不够则少抽。抽出的 PDF 内，对命中的**条款号**写入与阅读器手动高亮同类的 **PDF 高亮注释**（不是另做一套显示），打开即可看到黄条；注释内容可带「迎审条款 ×××」。  
2. **只要正文。** 目录页、附录页不作为命中页（条款本身就是「附录×」时除外）。多命中时优先正文落点（条款号作标题、前后有应当/负责等正文语气），排除目录点线页码、手册末页附件索引等。  
3. **条款号边界。** 禁止把更长编号的后缀当成命中，例如 `4.9.2.3` 不得匹配 `9.2.3`（匹配前不得紧邻数字或小数点）。定位与高亮均遵守此边界。  
4. **书名与文件映射。** 声明里的《手册正式名》与磁盘文件名可能不一致（如声明写《航空安全保卫方案》，文件名为「航空安保方案」）；按用户确认的别名表映射，映射不到则该条失败并记录，不猜。  
5. **文件夹与命名。** 目录怎么建、文件怎么起名，一律按主人当次说明执行。主人未指定时：每个条款一个 PDF，命名可用 `{原手册文件名提炼的手册名}{条款号}.pdf`（不加页码），先给出预览再落盘；不默认某一类审计专用目录（例如按审计点编号分文件夹）。文件夹内不放索引文件，除非主人要求。  
6. **高亮失败时。** 页已抽出但搜索不到可高亮矩形（版式/字体导致）时：仍保留抽页结果，并在报告中记「未加上高亮」，不假装已高亮。

### 作业顺序

1. 过滤目标行 → 解析符合性声明中的《手册》与条款号。  
2. 预检：每条能否在对应 PDF 正文页定位；汇总命中/无 PDF/无正文页。  
3. 用户确认预检结果后，按规则批量抽页、写入高亮注释，输出到目录。  
4. 抽完用阅读器抽查：条款号是否黄条、有无误高亮（短编号后缀）、目录/附录是否误入。
