# 文档维护与合并下载

## 文档分工

`spec/README.md` 是统一目录；`system/` 描述系统架构、重建验收、核对证据和文档交付；`dev/<entry>/` 描述业务输入、算法、输出、错误、状态与代码职责；`user/<entry>/manual.md` 描述准备、操作、结果含义和注意事项。

同一业务数字只在其权威规则中完整维护，其他页面引用该规则；不能在 Skill、用户手册、组件和系统文档中各造一套口径。培训皇帝的规则单列，教程内容与原始手册来源另列，避免将工程操作混进员工知识正文。

这种组织参考 `piyanzi` 的能力目录与配套资源清单：每项都说明做什么、需要什么、产出什么。看门狗另需系统架构、状态与文件契约、验收证据；不能把开发文档仅写成 Agent 提示词。

## 一项工具规格的完整度标准

| 内容 | 必须能回答的问题 |
| --- | --- |
| 范围与角色 | 谁使用、解决什么、哪些输出仍需人工决定？ |
| 输入契约 | 文件类型、表头、表头行、sheet 规则、必需/可选字段、主键、日期和重复记录如何处理？ |
| 规则与示例 | 优先级、公式、窗口端点、空值、异常与分支是什么，给定输入应输出什么？ |
| 状态与生命周期 | 何时可执行，参数变更如何使旧结果失效，失败/取消/重试/恢复影响什么？ |
| 输出契约 | 文件名、sheet、列顺序、单元格类型、公式/链接、顺序、来源和问题如何保留？ |
| 架构与资源 | 哪层读写、计算、管理状态、展示，模板/库/字体/外部系统在哪里？ |
| 验收 | 合成输入、期望值、测试位置、真实环境边界是什么？ |

此表是完整度判定标准，不代表现有每项已经把全部底层分支逐条写完。短工具可以用短规格，复杂规则须给足条件和失败分支；不能为了目录整齐复制没有业务内容的模板。

## 修改与版本管理

业务行为变化时同一次提交修改代码、核心测试和对应 dev/user；架构或分发变化同步系统文档，新增工具同步目录。修订记录由 Git 管理，合并文件保留文档正文和来源路径。

文档只记录当前规则和已确认的边界。核对表必须说明检查层级；未验证事项保留为边界，不能将其写成已通过。

## 合并文件契约

网页首页和开发者页的“下载开发文档”指向同一个 `downloads/watchdog-development-documentation.md`，保存文件名为 `watchdog开发者文档-YYYY-MM-DD.md`，日期使用下载当天浏览器本地日历日。页面初始化及点击时更新文件名，跨夜打开的页面也使用点击当天日期。这是单个 Markdown 文件，中文正文保持 UTF-8 无 BOM。

构建从 `spec/` 递归扫描全部 Markdown 文档，不维护逐篇白名单。`README.md` 在前，其他文档按路径稳定排序；每篇保留源路径和完整正文。测量 JSON 等非 Markdown 文件不参与合并。拒绝文档中的损坏 UTF-8、BOM、二进制内容或目录中的符号链接，不用替换字符掩盖源问题。

每篇有唯一英文锚点；篇内标题有对应锚点，文档相对链接与片段链接重写到合并文件内。代码围栏中的路径和链接示例原样保留；外部 HTTP 链接保留。源文件不存在或目标标题不存在时构建失败。合并文档不嵌入源码、本地库、业务模板或原始手册。

`scripts/documentation-export.mts` 处理扫描、文本校验、链接与合并；`scripts/build.mts` 在生产构建中调用它。产物只写 `dist`，不回写 spec。文件包含目录、来源路径与正文，固定排序且不写当前时间或本机路径，参与确定性双构建。`src/tool/documentation-download.ts` 负责两页面的下载文件名，日期不写入文档正文。

## 生成与验证

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run verify
```

以上每个命令均包含生产构建，因此重新扫描并输出当前文档。`npm.cmd run test:unit`、`test:tool`、`test:smoke`、`test:watch` 也有构建前置；watch 只在启动时构建，后续文档修改需重启或另跑 build。`test:python`、`test:habitats` 和直接 `npx.cmd vitest run` 是局部入口，不承担重新打包职责。

推送到 `master` 后，`.github/workflows/deploy-pages.yml` 在上传站点产物前执行完整 `verify`，其中构建生成合并文档，测试检查全部工具 dev/user 覆盖和内部链接。验证通过后，文档与 app 一同发布到静态站点；网页下载直接读取该文件。

Python 导出测试使用临时目录生成样本 Excel，退出测试上下文时删除目录和文件。锁班 runner 测试捕获创建提示并断言临时目录已删除。确定性构建的两个输出目录也在结束时清理。`dist/` 保留最近一次正式构建结果，每次构建替换原内容。

局部测试验证新增/删除文档、中文保真、代码块、锚点、错误拒绝、测量附件排除、重复输出一致和下载日期；生产产物验证工具 dev/user 覆盖、正文内容和页面链接。自动检查不能证明业务判断正确，也不能证明仅靠文档已经独立重建全部工具。
