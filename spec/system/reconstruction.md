# 重建与验收

## 两种恢复目标

**有源码的恢复**要求保留源码、锁文件、本地库、模板、知识源和配置，在清洁环境重新构建与验证。**仅依据文档的重建**要求重新实现业务行为和运行边界，可以采用新的内部文件划分，但必须对同一输入得到符合规格的结果。二者不能用“构建成功”这一项互相替代。

现有文档可用于理解架构、确定功能边界和实施重建；它没有逐项枚举所有界面、底层文件格式算法、模板字节和知识正文。当前没有脱离原源码独立重建通过的证据。只保存本文档合并文件不构成完整系统备份。

## 必须一起管理的资源

| 资源 | 位置或来源 | 缺失的影响 |
| --- | --- | --- |
| npm 精确依赖 | `package-lock.json`、`package.json` | 同版本依赖恢复和确定性验证失去依据 |
| Python 依赖 | 根及各 APP 的 `requirements.txt` | 本机 APP 和 Python 验证不能完整运行 |
| 浏览器库及授权 | `public/libs/versions.json` 与对应文件 | PDF、Excel、Word、图表和图片功能失效 |
| 默认花名册 | `public/template/机组花名册.xlsx` | 默认数据加载缺失；需要 owner 提供允许分发的替代文件，不能凭文档编造人员 |
| 外籍航线模板 | `public/template/foreign-route-approval/approval-template.xlsx` | 机场与俄罗斯查询表、公式、样式和打印设置缺失 |
| 培训资料模板 | `public/template/training-attendance/`、`public/template/training-notice/` | 签到资料及通知的版式、容量和 XML 映射失去依据 |
| 教程知识正文 | `src/tool/app/beginner-tutorial/content/` | 只有界面与操作说明，不能还原所有等级/资质记录 |
| 印章字体与授权 | `public/tool/app/seal-generator/fonts/`、`sources.json` | 字形和导出字体嵌入不可复原 |
| 备忘录正文及图片 | `public/memo/memos/`、两份索引 | 无法还原日常知识子站 |
| 公共样式、静态组件 | `public/theme.*`、`public/tool/habitats/` 等 | 全站主题和背景行为缺失 |
| 自动化工作台资源 | `public/tool/app/lock-entry-helper/`、`flight-stats-helper/`、`oa-read-helper/` | 本机入口、页面和门户动作链缺失 |
| 门户与 OA 的实际接口证据 | owner 的内网页面、账号权限、DOM 和日志 | 离线测试不能证明真实提交成功 |
| 原始手册与个人记录 | owner 提供的有效版本 | 无法重新确认教程业务内容和实际资格，不能由程序文档代替 |

资源随其自身发布权限保存，真实业务工作簿、生产结果、认证状态和账号不打入公共文档。资源目录在这里声明，不等于它已包含在合并下载文件中。

## 有源码时的恢复

在清洁目录取得完整仓库与上述受管理资源后执行：

```powershell
npm.cmd ci
python -m pip install -r requirements.txt
npm.cmd run verify
```

verify 成功后检查 `dist/index.html`、`dist/tool/index.html`、`dist/memo/index.html`、`dist/tool/developer.html`、每个工具入口与 `dist/exports/<entry>.zip`。合并文档为 `dist/downloads/watchdog-development-documentation.md`。`dist` 可以静态托管，生产站点不需要常驻 Node/Python。

临时本地检查可以执行 `python start_index.py --no-build --no-open --port 4567`。入口只监听本机，端口占用时报错；检查后结束本次服务并确认端口释放。Python APP 的浏览器安装和启动按各工具用户手册执行，不能把网站 HTTP 服务当作自动化 APP 的后台。

## 依据文档重建的实施顺序与门槛

下表是重建验收合同，不代表这些重建步骤已经执行。

| 顺序 | 必须完成的结果 | 可判定通过的证据 |
| --- | --- | --- |
| 1. 盘点 | 列出工具标识、公共子系统、输入结构、输出和依赖 | 与[工具目录](../README.md)逐项对应，无默认丢弃的弃用工具 |
| 2. 公共底座 | 静态部署、主题、入口清单、类型检查和文件下载可工作 | 子路径页面资源可解析，一个页面一个内部应用入口 |
| 3. 规则模型 | 将各工具输入归一、计算和问题记录从界面中分离 | 不打开浏览器也能对合成输入断言结果 |
| 4. 文件契约 | 实现表头、单元格类型、源位置、顺序和导出结构 | 重新读取导出文件，逐 sheet、表头、值、超链接/公式核验 |
| 5. 状态与恢复 | 实现筛选、人工调整、异步失效和项目导入边界 | 恢复不丢人、不重复；坏文件不替换现有项目；失败可追踪 |
| 6. 工具独立分发 | 27 个工具按自身资源闭包导出 | ZIP 数量等于工具清单；模板、Worker、字体和数据可离线获取 |
| 7. 文档交付 | 合并全体 spec，入口和内容与本次构建相同 | 新增/删除文档自动反映；中文和代码块保真；内部链接可定位 |
| 8. 整体验证 | 自动业务测试、静态接线和确定性构建通过 | verify 成功；额外背景脚本用 test:habitats 验证 |
| 9. 业务复核 | 视觉与真实输入结果经 owner 核对，内网动作有实际证据 | 人工确认记录；不能以模拟 worker 或按钮存在代替实际提交 |

## 跨工具不可混用的口径

- 人员结构统计不按 `是否运行` 筛人；实力周报只统计 `是否运行 = 是`。CRM 的应参加范围又不能照搬不飞人员的资质监控过滤。
- 重点人员标注以姓名匹配；运行资质比对以员工号匹配；英语汉语比对因编号体系不同以姓名匹配。不能统一替换成一种主键。
- “资质字段非空”的判定按各工具规格执行：体检 RAMA 只认可规定的 `1`/真值；实力周报排除一组无效文本；运行资质表用 `1`/`2` 表示角色。
- 培训“机器看”“已录入”“取消”“历史培训”“覆盖本轮”是不同概念。危险品截止前一日与语言截止当日不同，基准月与最新日期规则不同。
- 排班压力的人项、实际培训的人天/班次、珠海核对的人次、航线班次统计的姓名单元格计数不能相加或互相替代。
- 顺序与重复次数是外籍批复等输出的一部分。集合相等不能证明逐行结果一致。

## 验收样例写法

每个业务分支至少给出“输入字段与值 → 参数 → 归一中间值 → 期望结果/问题 → 导出位置”，并说明来源。例：国际反推最近日期为 `2026-11-06`，年限 1、重叠 0，目标为 `2027-11-30`；不按 11 月 6 日输出周年日。例：航线一个机组单元格含合成姓名“甲、乙”，花名册均存在时各加 1 班，不将重复书写的甲计成两班。

样例使用虚构人员，不依赖真实花名册；精确模板和知识正文仍须另行保管。[规格核对](alignment.md)列出了已有证据和仍不能据此宣称完整的部分。
