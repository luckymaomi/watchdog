# 菜鸟教程开发规格

菜鸟教程是工具首页的 Beta 工具，位置由工具清单顺序决定，面向南货航新员工，提供飞行人员转机型、技术等级、教员考试员、运行资质和资格恢复规则的可查询知识库。它不是开发者手册、Agent Skill 或原始 Word 文件阅读器。

## 知识边界

正文只使用两本已核对的现行手册：

- 《飞行人员训练大纲》R03-01 V6
- 《飞行技术管理手册》R01-08 V1

培训皇帝和备忘录只能作为发现问题的线索，不能替代原始手册证据。所有条目必须经过适用对象、起算事件、经历字段、训练检查顺序、合格与失败结果、签注、聘任、审批发布和系统入库的语义审计。

## 内容源

知识源位于 src/tool/app/beginner-tutorial/content/：

- manifest.json：声明知识库基本信息、来源文件和模块文件顺序。
- sources.json：集中维护两本手册的版本、章节和语义范围。
- modules/same-type-transfer.json：维护外公司飞行人员同型别转入时，临时转入与非临时转入各自适用的训练、检查、经历和运行资质恢复要求。
- modules/copilot-type-transition.json、captain-type-transition.json：维护两类转机型完整事件链。
- modules/copilot-levels.json、captain-levels.json：维护技术等级、运行权限和成长条件。
- modules/instructors-examiners.json、qualification-catalog.json：维护教员考试员和资质条目。
- modules/recovery.json：按失效原因维护完整恢复决策分支，同时作为等级页可复用的恢复规则源。
- modules/key-numbers.json：维护容易混淆的时间、经历和课时数字。
- special-categories.md：维护不适合等级表或统一字段的特殊类别与例外。

本轮语义模型还必须保持以下字段边界：航段、飞行次数、起落、人工飞行时间、PF/PM、昼间/夜间、模拟机课时、航线检查和资质能力专项检查分别记录。A2航线检查明确包含作为PF、昼间、带指引ILS的航段；机长转机型分别记录右座航段、左座操作驾驶员航段、夜航航段、人工飞行航段和技术检查航段。手册未规定的PF/PM或昼夜组合不得由构建或页面推断。转机型训练的适用对象是曾在相同组类不同型别飞机的相同职务上经审定合格并服务过的机组成员；同型别转入按外公司飞行人员转入的附加训练要求办理。

恢复模块必须覆盖近期经历、航线飞行间断超过6个月、复训/熟练检查逾期、实践或熟练检查不合格、年度航线检查、120天100小时、教员权利失效、资质能力专项检查、飞行技术专项检查以及技术/CRM胜任力缺陷恢复。航线飞行间断、近期经历不足和复训/熟练检查逾期是三个不同触发事件，不得共用一个恢复结论。局方或公司要求的资质能力专项检查只确认由飞行部形成书面实施材料，手册没有统一恢复数字时必须标记为部分确认，不得借用其他专项检查流程。英语通信检查必须保留评分结果分支；专项运行资质至少覆盖I类ILS自动着陆、LVO、RNP APCH和目视进近的PF/PM位置要求。

资质目录还必须独立覆盖RVSM、UPRT、飞行作风、初阶EBT、除冰防冰和目视进近。涉及周期、考试分数、课时、PF/PM位置、着陆/复飞或补训触发条件时，按各章原有业务对象维护，不能压缩成一个没有失败分支的“其他培训”条目。

源文件按业务变化原因拆分，浏览器不直接加载这些文件。构建时仍生成一个 dist/tool/beginner-tutorial-data.json。

## 内容模型

普通等级和资质记录包含适用对象、摘要、完整动作、状态与限制、来源，以及可选的分段正文。转机型和同型别转入使用顺序流程；普通等级使用可展开详情；重新获得资格使用按事件和失败次数划分的分支；特殊类别使用自由文章，不强制套用同一表格。

等级、资质和转机型记录只在确实需要回答“失效后怎么办”时，通过 `recoveryRecordIds` 引用恢复模块中的权威记录。构建时只输出一份完整权威记录，并从目标记录解析标题和摘要；不维护成长路径关联、关系类型或反向引用。

技术等级与运行资格必须分开表达。近期经历、复训或专项资质失效时，写明暂停或失去相应运行资格；只有手册明确规定降为巡航机长、D类副驾驶等情形时，才写技术等级发生变化。训练检查完成后，适用的执照签注、聘任、资质审批发布和排班系统入库仍属于最终生效链。

副驾驶A1阶段从本场模拟机训练检查合格后开始。A1转A2的25小时、PF/PM航段、起落和人工飞行时间是同一阶段的不同记录字段，页面必须同时列出，不能解释成两套独立的25小时要求。

资深副驾驶属于D类标准下只履行右座副驾驶职责的替代发展通道，不是A1至D主线之后的新技术等级，也不参加机长升级训练及带飞；应放在特殊类别中说明，不扩展主等级链。

同型别转入路径必须区分临时转入与非临时转入。临时转入且不涉及转机型的人员按CCAR-121部第415条完成训练和各项经历，参加运行前完成包含第121.439条完整复训要求的新雇员训练、第121.465条熟练检查和第457条新职位运行经历。非临时同型别转入人员可按AC-121-FS-2014-48第8.3条向局方申请使用缩减的复训课程；获批后完成新雇员训练及半年复训中的理论课程、模拟机训练和熟练检查，并按需更改基准月。来自南方航空公司或培训体系等效于南方航空公司且具有B777资质者，完成规定训练和检查后恢复原公司所具备的B777机型运行资质。同型别转入人员失去近期经历要求或失去资格时，完成重新获得资格训练。

## 构建与校验

scripts/beginner-tutorial-content.mts 负责：

- 读取 manifest、来源和分主题模块。
- 拒绝重复的来源、模块和记录ID。
- 解析 sourceIds 和 recoveryRecordIds；恢复目标不存在、目标不属于 recovery 模块或记录重复时直接终止构建。
- 发现未知来源或断开的恢复目标时直接终止构建。
- 将Markdown、来源和恢复规则入口装配为单一页面数据文件。

页面提供模块导航、全文搜索、记录锚点、跨模块跳转、浏览器历史返回和整体Markdown导出。转机型和恢复条目默认展开；等级、资质和教员条目按记录展开，展开后完整显示当前动作、权限、失效与恢复分支。记录只在有直接适用恢复入口时显示“恢复规则”区块，点击后进入唯一权威详情；详情只保留一个返回入口，不显示引用关系网络。内部跳转使用稳定模块/记录hash，支持浏览器后退和前进。折叠控件使用加号和减号，不使用箭头。页面接入共享主题，只使用完整边框和中性结构分隔，不使用彩色单边强调。

Markdown导出直接消费页面已校验的`BeginnerTutorialData`，不得维护第二份教程正文。导出按钮在数据加载前和加载失败时保持禁用；加载成功后生成单个`.md`文件。文件按manifest模块顺序包含使用边界、来源索引、模块正文、步骤、全部权威记录字段、结构化分段和恢复规则锚点链接，权威记录通过稳定锚点只出现一次，末尾附同源完整JSON；不包含搜索词、展开状态或反向引用等运行时/关系网络信息。

## 验收

- 核心知识装配测试验证两类转机型、A1经历字段、18分钟近期经历要求、二次审计新增专项训练和关键失败终态。
- Markdown完整性测试遍历全部模块、步骤、权威记录和恢复链接，验证每条权威记录锚点只出现一次、导出不含完整嵌入副本，并验证页面导出按钮初始禁用。
- npm.cmd run build 生成单一知识数据、页面脚本和样式。
- npm.cmd run typecheck 和 npm.cmd test 通过。
- npm.cmd run verify:deterministic 通过。
- 不使用真实浏览器自动化；页面最终视觉和实际滚动体验由owner人工检查。
